## Executive Assessment

Fabric is a useful and worthwhile Go library. It is not wasted work. The core
idea is strong: a compact fluent SQL abstraction that stays close to SQL while
handling common cross-dialect differences for MySQL, PostgreSQL, SQLite, and
MSSQL.

The v1 surface has a coherent shape: fluent query builders, SQL preview,
parameterized conditions, safe aggregate filtering, typed row scanning,
transactions, retry helpers, pool statistics, logging, tracing, and an optional
Manager package for multi-entry routing. The strongest parts are the SQL
builder, dialect capability layer, transaction semantics, and explicit error
behavior for unsupported SQL shapes.

## What Fabric Is Good At

- SQL-first applications that need dynamic query construction.
- Teams that want less ceremony than an ORM but more structure than raw SQL
  string assembly.
- Multi-dialect projects targeting MySQL, PostgreSQL, SQLite, and MSSQL.
- Tests and debugging workflows that benefit from generated SQL preview.
- Typed row scanning without adopting code generation.
- Controlled production services where supported dialects are covered in CI.

## Current Strengths

- Fluent builders cover SELECT, INSERT, UPDATE, and DELETE.
- `Query()`/`SelectQuery()` and mutation preview helpers expose generated SQL
  and args.
- PostgreSQL `RETURNING` and MSSQL `OUTPUT` are available in query preview.
- Mutation execution returns `ExecResult`; returning/output execution is
  rejected clearly because execution does not return rows.
- `Having(condition)` keeps aggregate filters parameterized, while
  `HavingRaw` remains available for trusted SQL fragments.
- Identifier quoting escapes dialect delimiters for MySQL, SQLite,
  PostgreSQL, and MSSQL.
- Dialect capabilities centralize decisions for pagination, returning/output,
  joined mutations, and mutation order/limit behavior.
- `WithTransaction` rolls back callback errors and panics and returns non-nil
  errors with context.
- Retry jitter is concurrency-safe.
- Rows adapter pool paths reset adapters before reuse.
- Manager lifecycle has explicit states, idempotent start/stop, worker wait
  groups, and clear closed/not-started errors.
- Integration tests support strict per-dialect runs and MSSQL test database
  setup through `master`.

## Relevant Findings

### 1. Live integration coverage must be part of release confidence

SQLite integration is easy to run locally, but cross-dialect confidence requires
MySQL, PostgreSQL, and MSSQL services in CI. Strict mode should be used for
release validation:

```text
FABRIC_INTEGRATION_STRICT=1
```

Run each dialect explicitly with `DB_TYPE` so unavailable services are treated
as failures.

### 2. Manager should receive workload soak

The Manager package has clear lifecycle semantics and race-checked tests. Its
remaining maturity work is operational: longer concurrent workloads with real
databases should exercise routing, health checks, shutdown, and queue
backpressure.

### 3. Raw SQL escape hatches are caller-owned

Fabric parameterizes values through conditions and builder data maps. Table
names, column names, raw expressions, raw `HAVING`, and raw query strings must
be trusted or allowlisted by callers.

### 4. Fabric is intentionally not an ORM

Fabric should be positioned as a SQL-first toolkit, not as a replacement for
sqlc, ent, GORM, Bun, or schema migration systems. Its strength is ergonomic
query construction and database operations without model lifecycle machinery.

## Usefulness Assessment

Fabric is most useful when:

- a project needs a small query-building abstraction across supported SQL
  databases;
- the team wants SQL-shaped code instead of an ORM model layer;
- generated SQL preview matters for tests, debugging, or review;
- database targets are known and covered by CI integration tests.

Fabric is less useful when:

- compile-time query checking is required;
- schema migrations and relationships are the main problem;
- arbitrary untrusted users control table, column, or raw SQL fragments;
- the application needs deep ORM identity mapping or eager-loading behavior.

```text

```

## Bottom Line

You did not waste time. Fabric is a credible v1 controlled-use library with an
A-level core. The next confidence gains should come from strict live
integration CI, longer Manager workload testing, and continued documentation
discipline around trusted identifiers and raw SQL.
